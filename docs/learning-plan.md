# SGLang Serving Lab 学习计划与进度

更新日期：2026-10-23。这里是学习路线、当前进度和下一步的唯一权威记录。
历史聊天用于补充背景；不要凭记忆把已完成任务重做，或把支线自动升级为主线。

## 学习目标与范围

围绕这个单 GPU 项目，理解并交付一个能解释、能部署、能观察、具备基础保护和恢复策略的 LLM serving 系统。
每个关键机制都能回答：解决什么问题、当前如何实现、怎么确认有效、有什么边界。
当前目标不是深入性能研究，也不把本地实验环境称为生产就绪平台。

## 当前接续点

- 当前阶段：5，基础可靠性与客户端行为。
- 已讲过：进程退出后的自动重启与健康检查的区别；服务恢复不等于中断请求恢复；总时间预算、有限重试、退避与抖动；流式输出开始后不自动从头重试。
- 尚未实现：带有限重试与总时间预算的客户端示例。不要把讲过当成已经完成。
- 下一步只做：实现一个非流式客户端示例和简短使用说明，沿用私有环境变量中的 API key。
- 该步最低验收：一个正常调用；小型本地模拟确认暂时性 503 可有限重试、401 不重试、总预算耗尽后停止。无需另建性能基准或破坏正在运行的服务。
- 15 秒预算、最多两次重试是课堂示例，尚未确定为项目默认值。

## 每次学习的固定流程

1. 开始：读取本文件，简短说明当前阶段、已完成什么、这次只推进哪一步。
2. 教学：围绕项目中的机制、代码与取舍；用户已要求跳过太基础的讲解。
3. 实践：为当前目标做最小必要验证。正常结果得到后就收尾；不要为了更完整不断扩大实验。
4. 收尾：记录改动、实际证据、未验证边界、提交状态，并更新当前接续点。
5. 按大纲给出一个下一步。若出现有趣支线，记入暂缓事项，继续主线。

每个小步骤的完成标准是：概念讲清楚、产物可查看、最小必要验证完成、边界明确。
不以继续研究能发现更多东西为理由延迟进入下一阶段。

## 协作与操作约定

- 默认使用中文，重视推理服务的工程取舍，不反复解释文件、端口等通用基础。
- 区分已讲解、已实现、已配置、已实测；不把推断写成验证结果。
- 不保存或展示密钥、`.env` 内容、真实用户请求；避免读取未脱敏的启动参数日志。
- 保留用户修改；变更运行服务前说明具体影响，尽可能只更新需要的服务。
- 文档变更无需增加测试；实现变更只做与目标相关的检查，不机械增加实验。
- 用户要求继续时，按当前接续点推进，不自动重开已完成阶段。
- 记录是否已提交/推送，不把本地改动描述成 GitHub 已更新。
- 版本控制文档负责持久化；新聊天仍需打开/读取仓库，不能保证仅凭聊天标题就自动加载这些记录。
